# Changes

## Unreleased

- **Code-along, for videos**: `code_along(stages=..., start=, duration=, layout=, typing_speed=, style=, run=, live=, font_scale=, callouts=)` shows code being typed on one side (syntax coloured, line numbers, a cursor, the changed lines lit, optional callouts with an arrow) and, on the other, what that code really draws at each stage. A Python stage is run here, in a namespace of its own with the preview's `width` and `height` and a fixed-step `update(dt)`, and what it draws is clipped into the preview; a JavaScript stage is run by the page. Stage 0 is typed from empty, each next stage types only what changed, and `duration` fits the typing and the holds to the beat. Wide frame: code beside the preview; tall: code above it. Text is never smaller than 3 percent of the frame's height; a long line is wrapped and reported in `warnings`. `code_along_stage_at(stages, t, ...)` says which stage and how many characters are typed at `t`. The plan and the layout are worked out in Python as well as in the page (`codealong.js`, pictures.js's own), and `tests/test_codealong.py` compares them with node, and the same JavaScript stage draws the same pixels from Python as from pictures.js. Stages can be timed to a voice-over (`at`, `type_at`, `type_time`), the stage's box is set in from the preview's edge (`preview_pad`), `say()` in a preview is silent and `mouth()` is sized to the preview (`demo_voice=True` makes it talk), and long lines are cut after a comma or an opening bracket. A scene that names none loads none of it. New docs page, Code-along; new example `code_along_circle.py`.
- **Kinetic text, for videos**: `word_slam`, `letter_wave`, `letter_bounce`, `typewriter_text`, `glitch_text`, `mask_reveal`, `scale_pop`, `ticker_text`, `count_up` and `highlight_sweep` draw moving words into the scene, with nothing to import, the same library as pictures.js's (the same call draws the same pixels). They lay themselves out from `width` and `height` (wrapped, inside the safe area of the shape, never under 3 percent of the height), take `start`, `duration`, `t`, `x`, `y`, `size`, `style` (playful, techy, calm), `colour`, `accent`, `beat`, `safe` and `seed`, and follow the scene's own seconds (`kinetic_time()`, the recorder's time when the scene is recorded). Also `kinetic_text`, `kinetic_safe`, `kinetic_effects`, `house_style` and `seeded_random`. The page's half is `kinetic/kinetic.js` (pictures.js's, brought by `scripts/sync_libraries.py`, which also writes the house style into `pykinetic.py`), handle 17, loaded only for a file that names one. A call gives back nothing. New docs page, Kinetic text; new examples `kinetic_gallery.py` and `hook.py`; `tests/test_kinetic.py`, which compares every effect's pixels with pictures.js's.
- **A talking mouth**: `mouth(x, y)` draws a mouth that is a line while the computer is quiet and opens with its voice, with `speaking()` and `voice_level()` (0 to 1) to make a face of your own. `mouth(x, y, size=None, style="oval", color="black")`: `style` is `"oval"`, `"smile"` or `"robot"`, `size` is its width (a sixth of the smaller side of the scene if left out). Nothing to set up beyond calling `say()`; a file that calls any of the four is given them. Pyctures has no second implementation: the page (pictures.js's `voice/say.js`, brought by `scripts/sync_libraries.py`) finds the level and draws the mouth, Python writes one command (`H_SAY`, "mouth", with the level it was told) and the page tells Python the level and whether it is speaking with each frame, so `voice_level()` is the level of the frame being drawn, also when a recorder steps the scene. A recorded line gives the real loudness of its audio at the frame's time; the free voice has no samples, so its level is made up from the words, seeded from the text so every run is the same: not true lip-sync, and the docs say so. The mouth has a shape as well as a level: `voice_shape()` gives `{"width", "height", "viseme"}` and the `"oval"` and `"smile"` mouths use it. A recording's shape comes from loudness and how often its wave crosses zero; the free voice goes syllable by syllable from the words (the vowel picks the shape, m, b and p close the lips first, word gaps close the mouth). The `say_hello` example is now a face, `mouth` and `say`. `tests/test_say.py`.
- **Casting**: `speaker(voice, like=..., fallback=...)` takes provider-qualified voice ids (`system:Samantha`, `kokoro:af_heart`, `hq:nova`, `draft:`; a bare name is read as `system:` first, then by name anywhere), a provider-neutral `like={"gender", "age", "pitch", "rate"}` and a `fallback` list of ids or presets. The draft voice picks the best device match for the voice, then each fallback, then `like`, then the default. A voice host may add `resolveVoice(spec) -> { voice, exact, note }`; `lookup` gets the resolved voice and every asked entry (`note`) gets `resolved` and `exact` (and `castNote`). New `castVoice` in `voice/say.js`.
- **Voices and characters**: `speaker(voice=None, pitch=1, rate=1, lang="en", name=None)` makes a character with a voice of its own, so two faces can talk to each other. `voice` is an exact voice name, a preset word (`"robot"`, `"high"`, `"deep"`, `"squeaky"`, `"slow"`, `"fast"`: each sets a pitch and a rate and looks for an installed voice that suits it, and works on any device by falling back to the device's default voice) or a host's voice id; the free voice honours `pitch` (0 to 2) and `rate` (0.1 to 4), a generated line is the host's to adjust. A speaker has `say(text)`, `say_at(text)`, `level()`, `shape()` and `speaking()`. Lines said by speakers go through one queue, in order, so a conversation never overlaps (a plain `say()` is not queued and is unchanged); `say_at(text, speaker=bob)` and `bob.say_at(text)` give `{"start", "duration", "end"}` in seconds from now, so a scene knows when a line begins. `mouth(x, y, speaker=bob)`, `voice_level(bob)`, `voice_shape(bob)` and `speaking(bob)` follow one speaker only (with no argument they mean the last or any speaker); the free voice's and a generated voice's mouths both work per speaker. `voices()` lists the voices on offer, a list of dictionaries with `name`, `lang`, `default` and `source`, English first (empty until the device has loaded its own). A voice host may add an optional `voices()`; a line a speaker says reaches `lookup`, `note` and `speakDraft` with the speaker's `voice` and, when they are not 1, `pitch` and `rate`, and `note` also gets the speaker's `name`. New in `voice/say.js`: `voicePresets`, `pickVoice`; `createSay` gives `sayAt`, `voices`, `speaker` and `onVoices`; the Python half is in `voice/pysay.py`. New docs section, Voices and characters; new example `two_faces.py`; `tests/test_say.py`.
- **The computer can talk**: `say("Hello")` says it, with nothing to import or set up, no account and no network: the voice is the device's own (the browser's speech). It gives back how many seconds the line takes, so a scene can wait for it: `await sleep(say("Hello"))`. `say(text, voice=None, lang="en")` picks a voice and a language. An app can supply better voices as a **voice host** (`mount(el, { src, voice: host })` or `window.pictureHost.voice`, with `lookup`, `note` and optional `speakDraft`): a line it has a recording of plays on the scene's clock, and in a scene recorded a frame at a time through the stepped sound, on the exact sample; the page tells Python the measured length of each line written out in the code before it starts (`info["say"]`), and of a line made while it runs with a later frame. The library never generates a voice. Every different line asked for is told to the host (`note`). The free voice cannot be recorded into a video, so a recorded scene reports each line with no recording, once, instead of dropping it. A part of its own, `voice/say.js` (pictures.js's, brought by `scripts/sync_libraries.py`) and `voice/pysay.py`, loaded only for a file that calls `say(`. `H_SAY` is handle 16. A new docs page, Make it talk. `tests/test_say.py`.
- **A recorded video has its sound, in step to the sample**: `mount(el, { src, stepped: { fps: 60 } })` runs a scene one frame for each `await scene.step()`, for a host that records it as a video. The scene's time is then the recorder's, in Python too (`sound_time()`, `beat()` and `sleep()` go by it: each frame says its time as `vt`), and its sound is made a frame at a time by a player with no sound card (synths.js's stepped player) and handed over as samples with `scene.sound.take()`: a note played in a frame begins on that frame's first sample, and n frames are `round(n × 48000 / fps)` samples. It is a file of its own, `stepped/stepped.js`, fetched only when a host asks for it, so a page that is never recorded is the size it was; an app that draws the frames itself (Circuitry's recorder) gives the page's sound keeper a `clock` and a `player` in its `sound` option. A scene's code does not change. Docs: "Recording a video with sound" in `docs/sound.md`, and the host's side in `docs/website.md`.
- **Effects**: `from pyvisualfx import *` gives a scene `glow(1)`, `trails(1.5)`, `kaleidoscope(8)`, `blur`, `crt`, `glitch`, `rain`, `snow` and ninety-four in all, done by the page's graphics card to everything the scene has drawn, 2D or 3D, in the order they are turned on. An effect's settings are attributes (`tail.zoom = 2`), `look("arcade")` is several at once, `plasma()`, `metaballs()`, `fire()` and the other backdrops need no drawing at all, and `shader(...)` is one of your own. `react(shine, "strength", "bass")` ties a setting to the scene's music in the page, and `bass()`, `mids()`, `highs()`, `loudness()` and `pulse()` are the same numbers for your own drawing. Each effect is one command and a changed setting one more; the effects are run once for each frame Python sends, on the `dt` the scene is given, so a recording is the same every time. A dial can turn an effect, and a change of scene is seen through them. The same with `pyctures run`, in a built folder and in a single `.html` file; a page loads them only for a scene that imports them, and a single-file page without them is the size it was. See [Effects](docs/effects.md).
- `S.dt`, for a library: the seconds the frame being sent was given (what `update(dt)` is told), and `None` when what is sent is not a frame. `H_EFFECTS` is handle 13.
- **Scenes**: a file can be several scenes, each with its own `setup`, `update`, `draw` and `on_` functions and its own variables on `self`, and each starting empty. `class Title(Scene):` is one, and `scene("title", draw=draw_title)` is one from plain functions. Every scene plays in the order written, the first one first; `go("Game")`, `go(Game)`, `next_scene()` and `restart()` change scene, and a scene with `length = 12` (seconds), `beats = 16` or `bars = 4` (of the sound library's tempo) ends by itself. `scene_time`, `scene_progress` and `scene_name` say where it is. The words are [Pymations'](https://github.com/johnwylie70/pymations) wherever the thing is the same, and pictures.js has the same in its own spelling. What the file makes at its top level is shared by every scene, a scene's own controls go when it ends, and a song goes on playing across scenes. Scenes are a library of their own in `web/scenes` (`scenes.js` and `pyscenes.py`) that a file does not import: a file that names a scene is given it, and no other file loads it or has it packed into its page, so a file with no scenes runs, and weighs, exactly what it did. A transition is drawn into a canvas of its own over the scene's, in real pixels and stepped by the page's frame time, so a recording that draws the scene's canvases has it. ## 0.2.0 (2026-10-11)

Everything written for 0.1.0 still runs. This release adds a quicker way to draw, a fuller way to read the keyboard, mouse and fingers, and sprites that can tell when they touch.

### New

- **Files**: `save_text("notes.txt", words)` and `save_json("level.json", value)` write a file, and `load_text("notes.txt", "")` and `load_json("level.json", {})` give back what it holds, or the second value if there is no such file. A path is from the scene's folder and cannot leave it.
- **Databases**: `db = open_database("scores")` opens a SQLite database (the file `scores.db`), making it if it is new. `db.query(sql, values...)` gives a list of rows, each a dictionary by column name; `db.run(sql, values...)` makes a change and gives the number of rows it changed; `db.close()` finishes with it. Values after the SQL go into its `?` marks in order.
- **Where they are kept**: with `pyctures run`, real files beside the scene. On a web page or a built page, in the browser, for that scene alone (text in `localStorage`, databases in IndexedDB), and until the page is closed where the browser will keep nothing. In a browser, SQLite is loaded only for a scene that says `open_database`.
- **`storage`**, for an app that shows scenes: `mount(el, { src, storage })` takes an object with any of `list`, `readText`, `writeText`, `readBytes` and `writeBytes`, so files and databases are real files where the app keeps them. See `docs/website.md`.
- A new example, Top Scores, and a new page, `docs/files-and-databases.md`.
- **Plain drawing functions**, one call each, nothing to import: `background`, `circle`, `ellipse`, `rect`, `triangle`, `polygon`, `star`, `line`, `text` and `picture`. A shape takes its colour as the last argument, and `outline=` and `thickness=` draw its edge. `ctx` is still there for everything else.
- **`random` and `pick`**: `random(1, 6)` is a whole number from 1 to 6, `random()` a fraction from 0 to 1, and `pick(list)` one thing from a list. `degrees(n)` gives an angle in degrees wherever an angle is wanted.
- **Keyboard**: `pressed` and `released` hold the keys that went down and came up since the last frame. `keys.shift`, `keys.ctrl`, `keys.alt` and `keys.meta` say which of those are held, and `keys.codes` holds keys by their place on the keyboard (`"KeyW"`), so WASD works on any layout. `on_key_repeat(key, code)` is called while a key is held.
- **Mouse**: `mouse.button`, `mouse.inside`, `mouse.dx`, `mouse.dy` and `mouse.wheel`, and `on_wheel(amount)`.
- **Touch**: `touches` is every finger that is down, each with where it is, where it began and how far it moved. `pinch` is two fingers as a zoom. `on_touch_start`, `on_touch_move`, `on_touch_end` and `on_pinch` are called as they happen.
- **Sprites that touch**: `sprite.touches(other)`, `sprite.hit(sprites)` and `sprite.contains(x, y)`. `Sprite.box(...)` and `Sprite.circle(...)` make a plain coloured box or circle, tested as the shape you see. `wrap()`, `bounce()`, `offscreen()`, `push()`, `forward()`, `limit()`, `angle_to()` and `distance_to()` move a sprite and aim it. `remove(things, thing)` takes one out of a list.
- **Saved values**: `save("best", 120)` keeps a value for the next time the program runs, and `load("best", 0)` gives it back (numbers, text, `True` or `False`, lists and dictionaries). It is kept in the browser's storage for that scene alone; where there is no storage it still works until the page is closed. See `docs/saved-values.md`.
- **A sprite's picture function can take the size alone**: `def draw_ship(size)`. `(ctx, size)` works as before.
- **Hit tests on their own**: `circles_touch`, `boxes_touch`, `circle_touches_box`, `point_in_circle` and `point_in_box`.
- **`vsync`**: another name for `frame`, for a program written as a loop: `await vsync()`.
- **Eleven more examples**: Hello, Moving, Follow, First Game, Ring, Night Sky, High Score, Space Rocks, Brick Breaker, Bat and Ball and Snake (which keeps its best score). The older examples now use the plain drawing functions where that makes them shorter.
- A new tutorial, Space Rocks, and the README starts with four small scenes that build up to a game.

### Different from 0.1.0

- The new names are there in every scene without importing: `circle`, `rect`, `line`, `text`, `background`, `random`, `pick`, `save`, `load`, `pressed`, `touches` and the rest. A scene that makes its own function or variable with one of those names keeps its own. `random` is also everything Python's own `random` module is, with or without `import random`: `random.choice(...)`, `random.uniform(...)` and `random.random()` work as before.
- A scene that uses the mouse now keeps a drag that leaves the picture, and a right-click in it is the right button, not the browser's menu.
- A scene that names the wheel (`on_wheel`, `mouse.wheel`) or the pinch takes it, so the page does not scroll or zoom under it. Under any other scene the wheel scrolls the page as before.
- When the scene loses the keyboard (you click away, or change window), the keys it thought were held are let go.
