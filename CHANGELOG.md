# Changes

## Unreleased

- **Scenes**: a file can be several scenes, each with its own `setup`, `update`, `draw` and `on_` functions and its own variables on `self`, and each starting empty. `class Title(Scene):` is one, and `scene("title", draw=draw_title)` is one from plain functions. Every scene plays in the order written, the first one first; `go("Game")`, `go(Game)`, `next_scene()` and `restart()` change scene, and a scene with `length = 12` (seconds), `beats = 16` or `bars = 4` (of the sound library's tempo) ends by itself. `scene_time`, `scene_progress` and `scene_name` say where it is. A scene arrives with a transition: `transition = "crossfade"` on it, or `go("Game", transition="wipe", transition_time=0.5)`, from `"cut"`, `"crossfade"`, `"fade"`, the four wipes and the four slides, in 2D and 3D. The page runs the transition, on a still picture of the old scene, so it is smooth however busy Python is. A program whose scenes all have a length has a scrubber with a tick where each starts, and `section("name")` adds a tick. The words are [Pymations'](https://github.com/johnwylie70/pymations) wherever the thing is the same, and pictures.js has the same in its own spelling. What the file makes at its top level is shared by every scene, a scene's own controls go when it ends, and a song goes on playing across scenes. Scenes are a library of their own in `web/scenes` (`scenes.js` and `pyscenes.py`) that a file does not import: a file that names a scene is given it, and no other file loads it or has it packed into its page, so a file with no scenes runs, and weighs, exactly what it did. A transition is drawn into a canvas of its own over the scene's, in real pixels and stepped by the page's frame time, so a recording that draws the scene's canvases has it. Pausing the scrubber pauses the sound. New docs page: Scenes. Two new examples: Three Screens and Three Parts.
- **`controls`** and **`transitions`**, for an app that shows scenes: `mount(el, { src, controls: false })` leaves out the scrubber, and `transitions` adds transitions by name (an effects library's). `scenes/scenes.js` exports `scenesKeeper`, `transitionLayer` and `timelineBar` for an app with a renderer of its own (and `mount`'s `scenes` option takes that module from a host that has it): the page's half of scenes is the fixed handle 12, and a page says it has it with `scenes` in the start info.
- **Sound**: `from synths import *` at the top of a scene gives it `play_sound("coin")`, `play_note("C4")`, `play_notes("C4 E4 G4 - C5", 0.25)`, `make_synth("lead")` with its settings as attributes, arpeggios, samples from a file, effects and `play_song("tune.mod")`. It is the library [synths](https://github.com/johnwylie70/synths-py), which comes with Pyctures; the sound is made by its engine on the browser's audio thread. A browser is silent until the page has been touched, and the scene says so until it has been. See `docs/sound.md`.
- **Dials and a keyboard**: `from pydials import *` gives a scene `dial`, `slider`, `button`, `toggle`, `select`, `keyboard`, `scope` and `meter`. A dial can be a number for the scene (`speed = dial("speed", 0, 10)`) or a setting of a synth (`dial("cutoff", lead, "cutoff")`), and a keyboard plays one. Keys and dials act on the synth in the page, so they are heard at once however busy Python is. It is the library [pydials](https://github.com/johnwylie70/pydials), which also comes with Pyctures. See `docs/dials.md`.
- The scenes on one page share one sound card and one engine, each with its own synths; a scene that is out of view is silent until it is seen again.
- Both work the same with `pyctures run`, in a built folder and in a single `.html` file, and need no `eval`. A page loads them only for a scene that imports them: a scene without sound or dials loads exactly what it did before.
- `pyctures build` takes along the sound files a scene names (`load_sample("sounds/kick.wav")`), as it does images.
- **`sound`**, for an app that shows scenes: `mount(el, { src, sound })` takes an object with any of `send` (take the commands and play them elsewhere), `read`, `synths`, `wasm`, `worklet`, `latency` and `onState`. `dials` gives the page its `dials.js`. See `docs/website.md`.
- Four new examples: Sound Catcher, Tune, Arpeggio Chords and Synth Panel.
- **MIDI**, in a scene with `from synths import *`. `lead.play_from_midi()` has a MIDI keyboard play a synth, and `lead.learn("cutoff")` or `lead.map_midi(74, "cutoff")` has a knob turn a setting and the dial tied to it; the page does both itself, so they are immediate however busy Python is. A scene's own `on_midi_note(note, velocity, channel)`, `on_midi_note_off`, `on_midi_control`, `on_midi` and `on_midi_devices` are called with what arrived, once a frame, each message with the time it happened. `send_midi_note("C4", 0.8, length="quarter")` and the rest send to a device at the exact time asked for, and `midi_devices()` says what is plugged in (the page answers a frame later). Where there is no MIDI the console says so once and the scene carries on. MIDI's file is fetched only by a scene that uses it, and a single `.html` file carries it only then. See `docs/sound.md`.
- **`midi`**, for an app that shows scenes: `mount(el, { src, midi })` takes a MIDI transport for a browser that has none (an iPad's web view), and `sound.onMidi` hands back what a host's own player received. See `docs/website.md`.
- Two new examples: MIDI Keyboard and MIDI Lights. Each is worth running with nothing plugged in.
- **Your voice**, in a scene with `from synths import *`. `mic = use_microphone()` is a synth whose sound comes in: `mic.voice = "robot"` (robot, chipmunk, monster, cave, telephone, alien, whisper), `mic.listen()` and `mic.mute()`, `mic.pitch`, `mic.ring`, `mic.comb`, `mic.gain`, `mic.gate` and every setting a synth has. The page asks the browser only when a scene calls it, and a dial, a switch or a picker tied to the microphone (`select("voice", mic, "voice")`) acts on it in the page, at once. Nothing is heard until `listen()`.
- **Recording and saving**: `take = record_sound(3)`, `start_recording()`, `stop_recording()`, `record_output(10)` and `lead.record(4)` give a take at once that plays like any sample; `take.done`, `take.seconds`, `take.on_done(fn)` and `await take.when_done()`. `save_sound(take, "hello.wav")` writes a WAV file beside the scene with `pyctures run`, and in a built page downloads it or gives it to the app that keeps the scene's files.
- The voice effects on every synth (`lead.voice`, `lead.pitch_shift`, `lead.ring_mod`, `lead.comb`, `lead.flanger`); a song's `mute`, `solo`, `loop_pattern`, `replace`, `position` and `channel(n)`; `lead.set(cutoff=4000, glide=2)`, with `slide` still understood.
- A sample as the wave of any synth: `lead.sample = load_sample("piano.wav")`, or `make_synth(sample="piano.wav", note="C4")`.
- The reverb has types: `set_effects(reverb_type="hall")` (room, hall, plate, cathedral, spring), with `reverb_decay`, `reverb_predelay` and `reverb_low_cut`. `pwm` and `pwm_rate` move a pulse wave's width. `load_samples({"C2": "piano-C2.wav", "C3": "piano-C3.wav"})` makes one instrument of several recordings, each playing the keys near its note (`kit=True` for a drum kit). `set_sound_buffer("large")` makes more sound at a time on a page with no https address, where a busy page clicks, and `sound_buffer()` says what it is.
- Controls lay themselves out: a `label` before some controls is the heading of their plate, `with group("filter"):`, `row`, `column`, `grid`, `spacer` and `wrap()` say what goes with what, `page("fx")` gives tabs, plates wrap evenly to fill the width and are moved with a finger when there is more than fits, `layout(wrap=False)` fits the rows as written to the width, `layout(size=[900, 640])` is a panel of a set size on every screen, any control takes `size="large"`, `room()` is the rectangle left for the scene, `rotary` is a knob that clicks between choices, and the piano keys slide to a new octave.
- More controls from `pydials`: for any program `number`, `text_box`, `readout`, `checkbox`, `choose`, `radio`, `dropdown`, `xy_pad`, `colour_picker`, `progress`, `light`, `busy`, `range_slider` and `fader`; for games `joystick`, `dpad` and `action_button`; for music `envelope`, `step_grid`, `pads`, `pitch_wheel`, `mod_wheel`, `steps`, `gate_pattern`, `arp_pattern` and `drum_seq`, a drum machine in one control.
- A `select` or `rotary` on a synth's `wave` offers `"sample"` only when that synth has a sample, and gains it when one is given.
- **Reading the sound back in Python**, for a scope, a meter or lit keys that a scene draws itself: `lead.samples()`, `lead.level()`, `lead.notes()`, the same on `sound_output()` and the microphone. What the page says reaches Python with the next frame, so these, `take.done`, `mic.state` and `song.position` are a frame late, and nothing waits for them.
- With no microphone (none plugged in, refused, a page that may not ask) nothing is raised: the console says why once, `mic.state` says which, and a recording is empty.
- A scene whose first line is `use_microphone()` says "Click, tap or press a key to turn the sound and the microphone on" until the page is touched.
- **`microphone`** and **`save`**, for an app that shows scenes: `mount(el, { src, microphone, save })` takes a stream, pushed frames or `false` in place of the browser's microphone, and is handed the files `save_sound` makes; `sound.onSoundEvents` and `sound.songPosition` carry back what a host's own player says. See `docs/website.md`.
- Two new examples: Voice Changer and Sampler. Each is worth running with no microphone.
- `scripts/sync_libraries.py` copies the two libraries into `src/pyctures/web/synths` and `src/pyctures/web/dials` from the repositories where they are written.

## 0.2.0 (2026-10-11)

Everything written for 0.1.0 still runs. This release adds a quicker way to draw, a fuller way to read the keyboard, mouse and fingers, and sprites that can tell when they touch.

### New

- **Files**: `save_text("notes.txt", words)` and `save_json("level.json", value)` write a file, and `load_text("notes.txt", "")` and `load_json("level.json", {})` give back what it holds, or the second value if there is no such file. A path is from the scene's folder and cannot leave it.
- **Databases**: `db = open_database("scores")` opens a SQLite database (the file `scores.db`), making it if it is new. `db.query(sql, values...)` gives a list of rows, each a dictionary by column name; `db.run(sql, values...)` makes a change and gives the number of rows it changed; `db.close()` finishes with it. Values after the SQL go into its `?` marks in order.
- **Where they are kept**: with `pyctures run`, real files beside the scene. On a web page or a built page, in the browser, for that scene alone (text in `localStorage`, databases in IndexedDB), and until the page is closed where the browser will keep nothing. In a browser, SQLite is loaded only for a scene that says `open_database`.
- **`storage`**, for an app that shows scenes: `mount(el, { src, storage })` takes an object with any of `list`, `readText`, `writeText`, `readBytes` and `writeBytes`, so files and databases are real files where the app keeps them. See `docs/website.md`.
- A new example, Top Scores, and a new page, `docs/files-and-databases.md`.
- **Plain drawing functions**, one call each, nothing to import: `background`, `circle`, `ellipse`, `rect`, `triangle`, `polygon`, `star`, `line`, `text` and `picture`. A shape takes its colour as the last argument, and `outline=` and `thickness=` draw its edge. `ctx` is still there for everything else.
- **`random` and `pick`**: `random(1, 6)` is a whole number from 1 to 6, `random()` a fraction from 0 to 1, and `pick(list)` one thing from a list. `degrees(n)` gives an angle in degrees wherever an angle is wanted.
- **Keyboard**: `pressed` and `released` hold the keys that went down and came up since the last frame. `keys.shift`, `keys.ctrl`, `keys.alt` and `keys.meta` say which of those are held, and `keys.codes` holds keys by their place on the keyboard (`"KeyW"`), so WASD works on any layout. `on_key_repeat(key, code)` is called while a key is held.
- **Mouse**: `mouse.button`, `mouse.inside`, `mouse.dx`, `mouse.dy` and `mouse.wheel`, and `on_wheel(amount)`.
- **Touch**: `touches` is every finger that is down, each with where it is, where it began and how far it moved. `pinch` is two fingers as a zoom. `on_touch_start`, `on_touch_move`, `on_touch_end` and `on_pinch` are called as they happen.
- **Sprites that touch**: `sprite.touches(other)`, `sprite.hit(sprites)` and `sprite.contains(x, y)`. `Sprite.box(...)` and `Sprite.circle(...)` make a plain coloured box or circle, tested as the shape you see. `wrap()`, `bounce()`, `offscreen()`, `push()`, `forward()`, `limit()`, `angle_to()` and `distance_to()` move a sprite and aim it. `remove(things, thing)` takes one out of a list.
- **Saved values**: `save("best", 120)` keeps a value for the next time the program runs, and `load("best", 0)` gives it back (numbers, text, `True` or `False`, lists and dictionaries). It is kept in the browser's storage for that scene alone; where there is no storage it still works until the page is closed. See `docs/saved-values.md`.
- **A sprite's picture function can take the size alone**: `def draw_ship(size)`. `(ctx, size)` works as before.
- **Hit tests on their own**: `circles_touch`, `boxes_touch`, `circle_touches_box`, `point_in_circle` and `point_in_box`.
- **`vsync`**: another name for `frame`, for a program written as a loop: `await vsync()`.
- **Eleven more examples**: Hello, Moving, Follow, First Game, Ring, Night Sky, High Score, Space Rocks, Brick Breaker, Bat and Ball and Snake (which keeps its best score). The older examples now use the plain drawing functions where that makes them shorter.
- A new tutorial, Space Rocks, and the README starts with four small scenes that build up to a game.

### Different from 0.1.0

- The new names are there in every scene without importing: `circle`, `rect`, `line`, `text`, `background`, `random`, `pick`, `save`, `load`, `pressed`, `touches` and the rest. A scene that makes its own function or variable with one of those names keeps its own. `random` is also everything Python's own `random` module is, with or without `import random`: `random.choice(...)`, `random.uniform(...)` and `random.random()` work as before.
- A scene that uses the mouse now keeps a drag that leaves the picture, and a right-click in it is the right button, not the browser's menu.
- A scene that names the wheel (`on_wheel`, `mouse.wheel`) or the pinch takes it, so the page does not scroll or zoom under it. Under any other scene the wheel scrolls the page as before.
- When the scene loses the keyboard (you click away, or change window), the keys it thought were held are let go.
